1. Functions & the DRY Principle

A function (or subroutine) is a self-contained, named block of code designed to perform a specific task and return a result. Packaging repeated logic into functions enforces the software engineering principle of DRY (Don't Repeat Yourself): every piece of business logic should have a single, unambiguous representation in the codebase.

In Python, a function is declared with the def keyword, followed by the function identifier, formal parameters in parentheses, a colon :, and an indented code block. In QBASIC, modular subroutines are declared with FUNCTION ... END FUNCTION or SUB ... END SUB.

The "One-Way Glass" Law of Variable Scope: Code inside a function can look outward and read global constants, but code outside in the main program cannot peek through the glass to read or tamper with local variables inside the function. When a local variable has the same name as a global variable, the local variable shadows (hides) the global one inside the function without altering the global variable outside.

def name(param1, param2=default):  →  local body  →  return value  (or None if omitted)

Modular Microgrid Tariff Calculator (calculate_nepa_bill)

Write a modular Python function calculate_nepa_bill(units, tariff_rate=68.0, vat_rate=0.075) with a fixed maintenance charge of ₦1,500.00. Call it for Meter 101 (85 units) and Meter 102 (210 units) and compute the exact outputs.

def calculate_nepa_bill(units, tariff_rate=68.0, vat_rate=0.075): energy_cost = units * tariff_rate vat_amount = energy_cost * vat_rate fixed_charge = 1500.0 total_bill = energy_cost + vat_amount + fixed_charge return round(total_bill, 2) household_1 = calculate_nepa_bill(85) household_2 = calculate_nepa_bill(210) print("Meter 101 Bill: N" + str(household_1)) print("Meter 102 Bill: N" + str(household_2))

  2. Call 2 (units = 210): energy_cost = 210 × 68.0 = 14280.0; vat_amount = 14280.0 × 0.075 = 1071.0; total_bill = 14280.0 + 1071.0 + 1500.0 = 16851.00.

Part A · Practical Home Investigation (Modular Tariff Blueprint)

Design a modular algorithm on paper (or in Python) that calculates the total monthly electricity bill for a household by decomposing the problem into three separate functions: (1) calculate_energy_cost(units, rate), (2) calculate_vat(energy_cost, vat_rate), and (3) generate_final_bill(units, rate, fixed_charge) which calls the first two functions and adds the fixed charge.

5 marks
Model solution & marking guidance unlocks after you try 
def calculate_energy_cost(units, rate):
    return units * rate

def calculate_vat(energy_cost, vat_rate=0.075):
    return energy_cost * vat_rate

def generate_final_bill(units, rate, fixed_charge=1500.0):
    energy = calculate_energy_cost(units, rate)
    vat = calculate_vat(energy, 0.075)
    return round(energy + vat + fixed_charge, 2)

Marking Guidance: Award 2 marks for clear function signatures (`def` + parameters), 2 marks for proper parameter passing and `return` usage, and 1 mark for modular composition (`generate_final_bill` calling the helper functions).

Modular programming is a software design technique that separates program functionality into independent, interchangeable modules or functions (1).

b2. Differentiate between formal parameters and actual arguments with a code example.

4 marks
Solution unlocks after you try

Formal parameters are the placeholder variable names listed in the function definition header (1). Actual arguments are the concrete values passed into the function when calling it (1).

def greet(name):       # 'name' is the formal parameter (1)
    print("Hello", name)

greet("Amina")         # '"Amina"' is the actual argument (1)

b3. Explain the difference between local scope and global scope, and describe what happens when a local variable has the same name as a global variable.

4 marks
Solution unlocks after you try

Global scope variables are declared outside functions and are accessible throughout the program (1). Local scope variables are created inside a function and are accessible only while that function executes (1). When a local variable shares the name of a global variable, the local variable shadows (takes precedence over) the global variable within the function, without modifying the global variable's value outside (2).

b6. What is a fruitful function compared to a void (procedure) function? Give one example of each.

4 marks
Solution unlocks after you try

A fruitful function computes and returns a specific value to the caller via a return statement (e.g. len("Ikogosi") returns 7) (2). A void function (procedure) performs an action (such as printing to screen or writing to a file) without returning a value (e.g. print("Hello")) (2).

b7. What does the return statement do besides passing a value back to the caller?

3 marks
Solution unlocks after you try

It immediately terminates function execution, popping the local stack frame and returning control back to the exact point where the function was called (3).

b8. Why is relying heavily on global variables considered poor programming practice?

3 marks
Solution unlocks after you try

It creates hidden dependencies between routines, makes code difficult to debug because any part of the program can unexpectedly overwrite the global variable, and makes functions harder to test or reuse in other programs (3).
