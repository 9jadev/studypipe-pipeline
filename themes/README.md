# Themes (visual templates)

A **theme** is the look of a unit: fonts, colours, corner roundness and a few optional component
tweaks. The **lesson shell** (page structure, LessonKit, SceneKit, StudyNarrator, StudyMath) is shared
by every theme and never changes per theme. Every topic picks one theme; switching costs one command.

```
themes/
├── default.txt            # theme used when a topic names none (editorial-ink)
├── catalog.md             # generated index: id, name, mood, fonts, audience (read before choosing)
├── gallery.html           # generated side-by-side phone previews: open in a browser to choose
├── _fonts/                # offline font library (woff2 + OFL licence + font.css per family)
│   └── fonts.json         # id → family, category, personality, files, KB
└── <theme-id>/
    ├── theme.json         # id, name, description, audience, mood, fonts{display,body,mono,math}, themeColor
    ├── theme.css          # :root tokens (all required) + optional component overrides
    └── preview/*.png      # generated by scripts/theme-preview.mjs
```

## Commands

| Do this | Command |
|---|---|
| List themes (`*` = default) | `node scripts/apply-theme.mjs --list` |
| Apply / switch a topic's theme | `node scripts/apply-theme.mjs topics/<slug> <theme-id>` |
| Re-apply the topic's recorded theme | `node scripts/apply-theme.mjs topics/<slug>` |
| Validate a theme (tokens, fonts, contrast) | `node scripts/check-theme.mjs <theme-id>` (or `--all`) |
| Screenshot a theme + rebuild gallery/catalog | `node scripts/theme-preview.mjs <theme-id>` (or `--all`) |
| Design a new theme with the human | skill `theme-designer` |

Which theme a topic uses is the `theme:` line in `topics/<slug>/status.md`. It can also be set when the
topic is created (`bash scripts/new-topic.sh <slug> <theme-id>`) or on its `queue.md` line (`- [ ] <slug> theme: <id>`).

## How a theme is applied

`apply-theme.mjs` (idempotent, never deletes custom CSS rules):
1. Rewrites literal colours, font names and pixel radii in `html/assets/css/*.css` into `var(--token)`
   (the map lives in `scripts/lib/theme-tokens.mjs`).
2. Copies only this theme's font files into `html/assets/fonts/` and writes `assets/css/fonts.css`.
3. Installs `assets/css/theme.css` and links it as the **last** stylesheet on every page, so it wins.
4. Sets `<meta name="theme-color">` from `theme.json`.

## The token contract

`theme.css` must define **every** token in `themes/editorial-ink/theme.css` (the reference theme);
`check-theme.mjs` fails otherwise. Groups:

| Group | Tokens | Rule |
|---|---|---|
| Fonts | `--font-display`, `--font-body`, `--font-mono`, `--font-math`, `--font-label` | First family must be the one `theme.json` names. `--font-math` should be a serif with a real italic (variables are italic). |
| Ink (dark surfaces) | `--ink-950 … --ink-600`, `--line`, `--line-strong`, `--fg`, `--fg-soft`, `--muted`, `--on-ink-soft` | Hub, lesson hero, nav, lab/quiz panels. **Must stay dark**: the shell puts white text on them. |
| Paper (light surfaces) | `--paper`, `--paper-2`, `--paper-card`, `--paper-ink`, `--paper-text`, `--paper-muted`, `--paper-faint`, `--paper-line` | Lesson reading sections and cards. **Must stay light**: dark text sits on them. |
| Accents | `--crimson` (heading emphasis, errors, phase colour), `--amber` (highlight, focus, active step) + `--on-amber`, `--pink`, `--pink-soft`, `--orange`, `--teal`, `--sky`, `--lime`, `--violet` | The names are historical roles, not required hues: Green Lab's `--amber` is lime. |
| Feedback | `--ok`, `--ok-deep`, `--ok-tint`, `--ok-tint-2`, `--bad-tint`, `--bad-tint-2`, `--warn`, `--info`, `--wall-notes` | `--ok` stays green-ish and `--crimson` red-ish: students read them as right/wrong. |
| RGB triplets | `--ink-950-rgb`, `--ink-900-rgb`, `--paper-rgb`, `--paper-ink-rgb`, `--crimson-rgb`, `--amber-rgb`, `--pink-rgb`, `--teal-rgb`, `--sky-rgb`, `--violet-rgb`, `--ok-rgb`, `--warn-rgb`, `--info-rgb` | `"r, g, b"` of the matching hex; used for translucent glows/tints. Checked automatically. |
| Shape | `--corner` (multiplies every small radius: 0.4 crisp … 1.5 bubbly), `--radius-sm`, `--radius`, `--radius-lg`, `--shadow-lg`, `--ease` | |

Contrast floors enforced by `check-theme.mjs`: `--fg` on ink ≥ 7, body text on paper cards ≥ 4.5,
`--on-amber` on amber ≥ 4.5, white on `--ok`/`--crimson`/`--info` ≥ 3, and more (see the script).

### Component overrides (below `:root`)

Allowed and encouraged for personality, as long as they are purely visual: heading weight/tracking/
leading, `em` styling (fonts without a true italic, such as Space Grotesk and Baloo 2, should set
`font-style: normal` and use colour), body size, section backgrounds and textures, button shapes.
**Never** hide elements, change layout grids, alter `.stage`/canvas sizing, or touch `.narr-*`
positioning: QA and the narrator depend on them. Keep overrides under ~60 lines.

## Fonts

Only fonts in `themes/_fonts/` may be used (everything must work offline, OFL-licensed). To add a family:
create `themes/_fonts/<id>/` with latin `.woff2` file(s), `OFL.txt` and a `font.css` whose `src` URLs are
`url("../fonts/<file>")`, then add it to `fonts.json`. Fontsource npm packages (`npm pack @fontsource-variable/<name>`)
are a convenient source. Keep each theme's fonts under **450 KB** in total; prefer variable fonts.

## Rules for anyone writing lesson CSS (renderer, kit-builder)

- Never hard-code a colour or font in shell or topic CSS when a token exists: use `var(--paper-card)`,
  `rgba(var(--ok-rgb), .1)`, `var(--font-mono)`. Re-running `apply-theme` tokenises known literals, but
  new one-off colours stay fixed across themes.
- 3D kit materials (apparatus colours) are content, not theme, and stay as they are.
